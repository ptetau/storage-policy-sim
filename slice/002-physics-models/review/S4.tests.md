# Review S4: tests

- major: [tests] test_002_S4_R12_physics_plan_prints_header_and_24_rows The test checks the exit code and that there are 25 lines. A version that prints 25 lines with a wrong header, wrong hour labels, rows with a missing column, or a discharge column that is not `yes` or `no` passes. The spec says the plan prints "its table of spec 001" with one row for each hour. Fix: assert the header words `hour forecast-kWh tank1-kWh discharge`, that row k has the hour k (0 to 23) as its first word, that each row has 4 words, and that the last word is `yes` or `no`. Do not assert the values of the requests, which the spec does not fix.
- major: [tests] test_002_S4_R12_physics_tune_prints_its_lines_and_table The test checks the shape of the output only, and no test shows that `tune` with `--model physics` differs from `tune` without it. R12 says `tune` uses `runPhysics`. A version that ignores `--model` for `tune` (it prints the simple tune) passes. `compare`, `robust` and `plan` each have a test that the physics output differs from the simple output; `tune` has none. Fix: add the same check for `sim policy tune` with `--days 30 --seeds 2`: both runs exit with 0 and the outputs differ.
