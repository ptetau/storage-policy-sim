# Review S9: tests

- major: [tests] test_001_S9_R23_forecast_column_is_plausible_for_mine_day_10 A version that prints the forecast of another day (for example day 0 instead of day 10), or a forecast made from another seed or another fetch hour, passes: the test checks only a zero at night, a positive sum and noon above midnight. The line "each with the forecast solar energy" has no test of the value. Fix: for the default home (one flat array, so `scenario`, `forecastOf` and `hourlyEnergy` apply), compute the 24 forecast values of the fetch at hour 24 x day, for a day other than 0 and a seed other than 1 (for example `--day 5 --seed 9 --days 30`), and compare each printed value with a tolerance of 0.05.
- major: [tests] test_001_S9_R23_heating_of_each_tank_equals_runHome_precomputed_day_10 The same fault in all the tests that parse the plan (also test_001_S9_R23_heating_follows_seed_and_days_options, test_001_S9_R23_no_day_option_prints_day_0 and test_001_S9_R23_last_day_364_is_accepted): the acceptance line says the heating equals the request "with one decimal", and D27 says plain numbers with no unit. A version that prints 3.2467 or `3.2kWh` passes, because the parser strips the unit and accepts any number of digits. Fix: in the row parser, fail when a number token has a unit or does not have exactly one digit after the point, and keep one test of this check on a day with heating.
- minor: [tests] test_001_S9_R23_plan_has_header_and_24_hour_rows_for_mine_day_10 A version with any non-numeric first line passes. D27 fixes the header: `hour`, `forecast-kWh`, one `tank<i>-kWh` for each tank, then `discharge`. Fix: assert the first word, the second word, the last word and the number of words (5 for the home `mine`), and not the numbering of the tank columns, which D27 leaves open.
